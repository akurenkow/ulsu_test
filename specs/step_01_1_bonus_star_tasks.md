# Бонусный шаг 1.1. Задачи со звёздочкой: Apache Airflow, Apache Superset, ClickHouse

## Цель шага

Расширить обязательную реализацию тремя бонусными технологиями из README (раздел «Задачи со звёздочкой (бонус)»):

- **Apache Airflow** — регулярный DAG вместо ручного запуска Python-пайплайна;
- **Apache Superset** — подключение витрин и демонстрационный дашборд;
- **ClickHouse** — перенос аналитического слоя или части витрин на `MergeTree` / `ReplacingMergeTree`.

## Связь с заданием

- README, раздел «Задачи со звёздочкой (бонус)».
- README, раздел «Технологический стек», блок «Задачи со звёздочкой».
- Требование README: *«Бонусные технологии не обязательны и не влияют на оценку базового прохождения задания. Их использование должно сохранять те же результаты, что и обязательная реализация.»*

## Входные артефакты

- Обязательные этапы 1–4: поднятый PostgreSQL 17, источник `deals_bigdata`, `etl/`, `sql/dwh/`, `ml/`.
- Этап 6 (разделы 6.3–6.5 перенесены сюда; в этапе 6 остался только пункт-ссылка).

## Общие принципы

1. Бонусы **аддитивны**: `docker compose up` по-прежнему поднимает обязательную часть без Airflow/Superset/ClickHouse.
2. Результаты бонусной реализации (число строк, суммы, перцентили, метрики ML) **совпадают** с обязательной частью.
3. Конфигурация — только через переменные окружения (`.env`/`.env.example`), без захардкоженных паролей.
4. Идемпотентность сохраняется: повторный прогон DAG/скоринга и повторная заливка витрин не дублируют данные.

## 1.1.1 ★ Apache Airflow — оркестрация пайплайна

**Цель.** Заменить ручной запуск этапов 2–4 регулярным DAG'ом: `init → ETL → пересчёт витрин → ML-скоринг`.

**Состав работ:**

1. Добавить сервисы Airflow в `docker-compose.yml` (или отдельный `docker-compose.airflow.yml`): `webserver`, `scheduler`, БД метаданных Airflow (отдельная от `deals_bigdata`/`dwh`). Минимальный вариант — `LocalExecutor` + PostgreSQL; `CeleryExecutor` + Redis — опционально.
2. Смонтировать `dags/` в `scheduler`/`webserver`; DAG-файлы — `dags/*.py`.
3. Реализовать DAG `etl_dwh_ml` (либо по одному DAG на стадию) со стадиями:
   - `init_source` — идемпотентная инициализация источника (переиспользовать логику `docker/postgres/init`);
   - `etl` — вызов `python -m etl.main` с окном дат из `logical_date` / `data_interval` (`start_date`/`end_date`);
   - `rebuild_marts` — пересчёт витрин `mart` (этап 3) с параметром `as_of`;
   - `ml_train_score` — обучение модели и batch-скоринг (этап 4).
4. Обеспечить **идемпотентность по `logical_date`**: повторный запуск за тот же интервал не дублирует строки (те же `UPSERT`/`DELETE + INSERT`, что в обязательной части).
5. Сконфигурировать подключения через Airflow Connections/Variables и env (`AIRFLOW__CORE__*`, `AIRFLOW_CONN_POSTGRES_ETL`, `N_PRICES`, `AS_OF`, `RANDOM_SEED`, `ML_RANDOM_SEED`, `LOG_LEVEL`), без паролей в коде.
6. Добавить `.env.example`-переменные Airflow и инструкцию запуска в README.

**Артефакты:**

- `dags/` — DAG(и) и вспомогательные операторы;
- сервисы Airflow в `docker-compose.yml` (или отдельный compose-файл);
- дополненный `.env.example`;
- README-раздел «Apache Airflow».

**Критерии приёмки:**

- [ ] Airflow поднимается одной командой (профиль/файл), UI доступен; без него `docker compose up` не трогает Airflow.
- [ ] DAG проходит полный цикл init → ETL → mart → ML за выбранный `logical_date`.
- [ ] Повторный запуск DAG за тот же интервал не меняет число строк/перцентили (идемпотентность).
- [ ] Результаты совпадают с ручным прогоном обязательной части.

## 1.1.2 ★ Apache Superset — BI-дашборд

**Цель.** Опубликовать результат (карточка маршрута, коридор P25–P50–P75, Data Trust) в Superset.

**Состав работ:**

1. Добавить сервис `superset` в `docker-compose.yml` (образ `apache/superset`), подключить к PostgreSQL `dwh` (схемы `core`/`mart`).
2. Настроить database connection к `dwh` через env, без паролей в коде.
3. Создать датасеты поверх витрин `mart_route_card` / `mart_market_corridor` (и, при наличии, `mart.ml_price_predictions`).
4. Подготовить демонстрационный дашборд:
   - карточка маршрута: медиана/квартили за рейс (`руб./рейс`) и за км (`руб./км`);
   - коридор ставок P25–P50–P75;
   - Data Trust: `trips_count`, `carriers_count`, `reliability_level`;
   - (опционально) «Факт vs Прогноз» по `mart.ml_price_predictions`.
5. Экспортировать дашборды/чарты в репозиторий (`superset/`) для воспроизводимости (`superset import-dashboards` или JSON-экспорт).

**Артефакты:**

- сервис Superset в `docker-compose.yml`;
- `superset/` — экспортированные дашборды/датасеты + инструкция импорта;
- README-раздел «Apache Superset».

**Критерии приёмки:**

- [ ] Superset поднимается одной командой и видит витрины `dwh.mart`.
- [ ] Дашборд воспроизводится импортом экспорта без ручной настройки чартов.
- [ ] Показатели дашборда совпадают с SQL-проверками витрин обязательной части.

## 1.1.3 ★ ClickHouse — аналитический слой

**Цель.** Перенести аналитический слой (или часть витрин) на ClickHouse, сохранив результаты обязательной реализации.

**Состав работ:**

1. Добавить сервис `clickhouse` в `docker-compose.yml` (`clickhouse/clickhouse-server`).
2. Выбрать и зафиксировать в README объём переноса:
   - вариант A — полный перенос витрин (`mart_route_card`, `mart.ml_price_predictions`);
   - вариант B — гибрид: детальные/сырые данные в ClickHouse, агрегаты остаются в PostgreSQL.
3. Спроектировать DDL на движках `MergeTree`/`ReplacingMergeTree`:
   - для витрин — ключ = grain (`месяц × город отпр. × город назн. × группа кузова × весовая категория`);
   - для прогнозов — ключ = (`price_id`, `model_name`).
4. Реализовать загрузку из `dwh` батчами (`INSERT ... SELECT` / `FORMAT` / `clickhouse-connect`), без построчных вставок.
5. Настроить дедупликацию при вставках: `ReplacingMergeTree` + `OPTIMIZE ... FINAL` (или чтение с `FINAL`).
6. Сверить результаты с PostgreSQL: число строк, контрольные суммы, перцентили.

**Артефакты:**

- сервис ClickHouse в `docker-compose.yml`;
- `sql/clickhouse/` — DDL движков `MergeTree`/`ReplacingMergeTree`;
- код загрузки/пересчёта (`etl/` или отдельный `clickhouse/`).

**Критерии приёмки:**

- [ ] ClickHouse поднимается одной командой.
- [ ] Число строк и контрольные суммы/перцентили в ClickHouse совпадают с PostgreSQL.
- [ ] Повторная загрузка не дублирует строки (`ReplacingMergeTree`).
