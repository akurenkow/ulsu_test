# Этап 1. Каркас проекта и инфраструктура

## Цель этапа

Подготовить запускаемый «скелет» проекта, который на чистой машине поднимается одной командой `docker-compose up` и на котором последующие этапы (`etl/`, `sql/`, `ml/`, `tests/`) будут строиться без переделок инфраструктуры.

## Связь с заданием

- Раздел README «Формат и условия выполнения»: развёртывание одной командой.
- Раздел «Нефункциональные требования»: чёткая структура репозитория, конфигурация через переменные окружения, отсутствие захардкоженных паролей и абсолютных путей.
- Раздел «Технологический стек»: PostgreSQL 17, Python 3.11+.
- Раздел «Схема входных данных»: быстрая инициализация источника (`sql/schema.sql` + `sql/synthetic.sql`).

## Входные артефакты

- [`sql/schema.sql`](../sql/schema.sql) — эталонная DDL операционной БД `deals_bigdata` (источник).
- [`sql/synthetic.sql`](../sql/synthetic.sql) — детерминированный генератор данных (`setseed(0.20261026)`, по умолчанию 300 000 сделок, снимок `2026-10-26`).
- [`README.md`](../README.md) — чек-лист сдачи и требования к артефактам.

## Задачи этапа

### 1.1 Структура репозитория

Создать каталоги, обязательные по чек-листу (и оставить места под опциональные):

```text
.
├── docker-compose.yml
├── .env.example
├── README.md                  # заглушка/скелет, наполняется на этапе 6
├── Dockerfile.etl             # образ для ETL (и, при необходимости, ML)
├── docker/
│   └── postgres/
│       └── init/              # скрипты инициализации контейнера
├── sql/
│   ├── schema.sql             # эталонная схема источника (из пакета)
│   ├── synthetic.sql          # генератор источника (из пакета)
│   └── dwh/                   # DDL Core DWH и Mart (этапы 2–3)
├── etl/                       # код пайплайна (этап 2)
├── ml/                        # код ML (этап 4)
├── tests/                     # pytest и SQL smoke-тесты (этап 5)
└── dags/                      # опционально: Apache Airflow (бонусный шаг 1.1, ★)
```

Решение по размещению эталонных файлов: исходные `sql/schema.sql` и `sql/synthetic.sql` сохраняются как есть (они задают операционный источник), а DDL хранилища (`core`/`mart`) располагается в `sql/dwh/` отдельно, чтобы не смешивать source и DWH.

### 1.2 PostgreSQL 17

- В `docker-compose.yml` поднять сервис `postgres` на образе `postgres:17`.
- Инициализировать **две** роли/схемы данных:
  - операционная БД-источник `deals_bigdata` (заполняется `schema.sql` + `synthetic.sql` на старте контейнера);
  - БД хранилища (например, `dwh`), в которой строятся слои `core` и `mart`.
- Допустимо упрощение: всё в одной БД `deals_bigdata`, но с чётко разделёнными схемами (`public` = источник, `core`, `mart`). Зафиксировать выбранный вариант в README.
- Настроить healthcheck (`pg_isready`) и `depends_on` для downstream-сервисов.

### 1.3 Инициализация источника

На старте контейнера выполнить в правильном порядке:

```bash
psql -U postgres -d deals_bigdata -v ON_ERROR_STOP=1 -f sql/schema.sql
psql -U postgres -d deals_bigdata -v ON_ERROR_STOP=1 -v n_prices=300000 -f sql/synthetic.sql
```

- Вынести `n_prices` в переменную окружения (`.env`) с дефолтом `300000`, чтобы данные можно было уменьшить/увеличить.
- Убедиться, что генератор отрабатывает с `setseed(0.20261026)` (детерминированность данных — требование воспроизводимости).

### 1.4 Образы приложений

- Создать `Dockerfile.etl` (Python 3.11+) с зависимостями для ETL: `pandas`/`polars`, `numpy`, `SQLAlchemy`/`psycopg`, `python-dotenv`, `structlog` (или стандартный `logging`).
- Для `ml/` — либо отдельный `Dockerfile.ml` (добавляются `scikit-learn`, `catboost`), либо один общий образ; выбор зафиксировать в README.
- Все зависимости зафиксировать в `requirements.txt`/`pyproject.toml` (пины версий).

### 1.5 Конфигурация и переменные окружения

- Создать `.env.example` с параметрами подключения (`POSTGRES_*`, `DWH_*`), `N_PRICES`, `AS_OF=2026-10-26`, `RANDOM_SEED=0.20261026` (для данных) и ML-зерном, путями, уровнями логирования.
- Никаких паролей и абсолютных путей локальной машины в коде. `.env` в `.gitignore`.

### 1.6 Логирование

- Завести единый утилитный модуль логирования (структурированный лог), которым будут пользоваться ETL (этап 2) и ML (этап 4).
- Логировать ключевые точки: сколько строк прочитано, сколько ушло в карантин, сколько записано/обновлено, какие метрики показала модель.

## Результаты (артефакты этапа)

- `docker-compose.yml`, `Dockerfile.etl` (и `Dockerfile.ml` при выборе отдельного образа).
- `.env.example`, `.gitignore`.
- `docker/postgres/init/*` — инициализация источника.
- `sql/schema.sql`, `sql/synthetic.sql` (скопированы из пакета).
- Каркас каталогов `etl/`, `ml/`, `tests/`, `sql/dwh/`.
- Модуль логирования.

## Критерии приёмки

- [ ] `docker-compose up` на чистой машине поднимает PostgreSQL 17 и инициализирует источник без ручных правок.
- [ ] `SELECT count(*) FROM prices;` возвращает 300 000 (при `N_PRICES=300000`).
- [ ] Повторный `docker-compose up`/пересоздание контейнера не дублирует данные источника (volumes + идемпотентный init).
- [ ] Структура каталогов соответствует чек-листу из README.
- [ ] Конфигурация читается только из переменных окружения.

## Зависимости

Нет (базовый этап). Все последующие этапы зависят от него.
