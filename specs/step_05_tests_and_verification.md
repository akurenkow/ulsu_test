# Этап 5. Автотесты и верификация

## Цель этапа

Покрыть ключевые правила решения автоматическими проверками, чтобы гарантировать корректность DQ-логики, идемпотентность пайплайнов, корректность витрин и отсутствие утечек в ML-признаках.

## Связь с заданием

- README, «Нефункциональные требования»: «наличие базовых автотестов (`pytest` или SQL smoke-проверок) на правила очистки данных, отсутствие дублей при повторном прогоне и корректность признаков будет весомым плюсом».

## Задачи этапа

### 5.1 Тесты правил очистки данных (DQ)

Проверить на фиксированных синтетических кейсах:
- `price <= 0` → карантин;
- `price <= 1000` для RUB → карантин (source-validation);
- `distance <= 0`, `total_weight < 0`, `total_volume < 0` → карантин;
- город отсутствует в `cities` → карантин;
- валюта 840/978 без точного курса по `nearest_rate_date` → карантин (fallback по `loading_date` **не** применяется);
- конвертация валют по точному курсу считается верно (в т. ч. RUB = 1.0);
- `weight_category`/`volume_category` на границах (`10.0`, `30.0`, `0`, `120`) и заполнение пропусков.

### 5.2 Тесты идемпотентности

- Двойной прогон ETL за один период → одинаковое число строк в `core.prices`, одинаковые контрольные суммы и перцентили, без дублей.
- Двойной пересчёт витрин `mart` → без дублей, метрики не меняются.
- Двойной скоринг ML → без дублей в `mart.ml_price_predictions`.

### 5.3 SQL smoke-проверки

- Витрина `mart_route_card`: наличие ожидаемых строк, неотрицательность `trips_count`, согласованность `P25 <= P50 <= P75`.
- Дедупликация городов: количество сделок с дублями `gc_id` не размножается (сравнение с контрольным `JOIN`).
- Унификация кузова: одна цена не дублируется внутри группы.

### 5.4 Тесты ML-признаков и защиты от утечек

- В матрице признаков отсутствуют запрещённые колонки (`price_with_vat`, `price/distance`, `price/total_weight`, поля `price_group_stats`).
- `outlier_mark` не входит в признаки.
- Разбиение `train/test` строго по `loading_date` без перемешивания; пересечение периодов отсутствует; границы соответствуют заданию.
- Циклические признаки лежат в диапазоне `[-1; 1]` и корректны для дат на стыке периодов.
- Все статистики импутации/масштабирования считаются только на `train`.
