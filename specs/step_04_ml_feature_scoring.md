## Задачи этапа

### 4.1 Feature Pipeline

#### География и маршрут
- Из дедуплицированного `cities` извлечь:
  - **регион отправления** и **регион назначения** из `full_name_local` (например, `'Казань, Республика Татарстан'` → город `'Казань'`, регион `'Республика Татарстан'`);
  - геокоординаты `latitude`, `longitude` (отправления и назначения).
- Кодировать отправление и назначение **раздельно** (регионы плотнее по сигналу на редких направлениях, чем склеенная строка маршрута высокой кардинальности).

#### Параметры груза и транспорта
- `distance` (плановое), `total_weight`, `total_volume`.
- Стандартизированная группа/тип кузова (`body_group` / `body_type`), весовая и объёмная категории.

#### Циклическое кодирование дат (Cyclical Time Encoding)
- Из `loading_date` извлечь `year`, `month`, `day of week`, `day of year`.
- Для циклических компонент рассчитать гармонические признаки:
  - день года `T = 365.25`;
  - месяц `T = 12`;
  - день недели `T = 7`.
- Формула: `sin(2π·t/T)`, `cos(2π·t/T)` (сохраняет близость 31.12 ↔ 01.01).

#### Предотвращение утечки данных (Data Leakage — критично)
Исключить из признакового пространства:
- ставку с НДС (`price_with_vat`);
- удельные тарифы текущего рейса: `price / distance`, `price / total_weight`;
- расчётные показатели маржи/прибыли (`carrier_cost = customer_cost - profit`);
- предрассчитанные групповые агрегаты текущего месяца из `price_group_stats` (`avg_price`, `min_km_price`, `max_km_price`, `price_group_id`) — в их расчёт уже вошла предсказываемая сделка.

Дополнительно:
- таргет очищается по предоставленному `outlier_mark`; **не** использовать `outlier_mark` как признак модели;
- `price_group_stats` запрещён как признак;
- любая дополнительная очистка по доверительному интервалу `ln(price_rub)` / IQR и обучение трансформеров (`SimpleImputer`, `StandardScaler`, `TargetEncoder`) выполняются **строго на `train`-выборке**.

### 4.2 Валидация, обучение и Batch Prediction

#### Временное разбиение (Time-Based Split)
- Только фактические прямые сделки: `is_fact = true`, `complex = false`.
- `as_of = 2026-10-26` (дата снимка, **не** системная дата запуска):
  - `train`: `[2026-07-26, 2026-10-05)` — `2026-07-26` включительно, `2026-10-05` не включительно;
  - `test`: `[2026-10-05, 2026-10-26]` — обе границы включительно.
- Граница `2026-10-05` входит только в `test`. `shuffle=True` на временных данных **недопустим**.

#### Модель
- Основная — `CatBoostRegressor` (нативная обработка `cat_features`, без масштабирования).
- Опционально сравнить с `Ridge` / `DecisionTreeRegressor` (scikit-learn).
- Зафиксировать `random_seed` (воспроизводимость), детерминированные границы `train/test`.

#### Метрики (на `test`)
- `R²`, `MAPE` (%), `RMSE` (руб.), `MAE` (руб.) — вывести в лог/отчёт.
- Ориентир из `ml-report.md`: CatBoost ~0.93 R² / ~13% MAPE (качественный ориентир, не цель).

#### Пакетный скоринг (Batch Inference)
- Скорировать отложенный тестовый период и плановые будущие заявки (`loading_date > '2026-10-26'`, присутствующие в датасете).
- Сохранить прогнозы в таблицу БД `mart.ml_price_predictions`:

| Поле | Назначение |
| :--- | :--- |
| `price_id` | ссылка на сделку |
| `loading_date` | дата погрузки |
| `loading_city_gcid` / `unloading_city_gcid` | маршрут |
| `body_group` | группа кузова |
| `actual_price_rub` | факт (для будущих заявок — `NULL`) |
| `predicted_price_rub` | прогноз |
| `abs_error_rub` | абсолютная ошибка (для будущих — `NULL`) |
| `ape_pct` | относительная ошибка (для будущих — `NULL`) |
| `model_name` | имя модели |
| `scored_at` | время скоринга |

- Для будущих заявок `actual_price_rub`, `abs_error_rub`, `ape_pct` = `NULL`, **даже если** в исходной строке заполнено поле `price`.

### 4.3 Воспроизводимость и идемпотентность скоринга

- Фиксированный `random_seed`, детерминированные границы `train/test`.
- Повторный скоринг за тот же период не дублирует строки в `mart.ml_price_predictions` (UPSERT по `price_id` + `model_name` / перезапись батча).

## Критерии приёмки

- [ ] Признаки не содержат производных таргета (`price_with_vat`, удельные тарифы, `price_group_stats` и т. д.).
- [ ] `outlier_mark` не используется как признак; очистка таргета — по нему.
- [ ] Разбиение строго по `loading_date` без перемешивания; границы соответствуют заданию.
- [ ] Циклические признаки дат построены корректно (день года, месяц, день недели).
- [ ] Метрики `R²`/`MAPE`/`RMSE`/`MAE` рассчитаны и выведены в лог.
- [ ] Прогнозы сохранены в `mart.ml_price_predictions`; у будущих заявок факт и ошибки `NULL`.
- [ ] Повторный запуск воспроизводим и идемпотентен.
